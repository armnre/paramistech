# پلن و گزارش کامل تغییرات — مهاجرت پارامیس‌تک به سرور اختصاصی

## هدف
اجرای کامل سایت (سایت عمومی + پرتال مشتری + پنل ادمین + سیستم مالی) روی سرور Ubuntu خودتان، با API و دیتابیس PostgreSQL، بدون وابستگی به پلتفرم قبلی، با همان قرارداد دپلوی پروژهٔ pinum-ambulance (sitectl).

## تصمیم معماری
- **کد برنامه دست‌نخورده می‌ماند**؛ endpointها (`apps/paramistech/src/api/*.ts`) و منطق مالی (`src/server/lib.ts`) عیناً روی Node اجرا می‌شوند.
- دو لایهٔ سازگاری (shim) جایگزین سرویس‌های پلتفرم شدند:
  - `deploy/server/zitejs-shim/db.mjs` → پیاده‌سازی کامل لایهٔ داده روی PostgreSQL (findAll/findOne/create/update/delete/bulkCreate/sql، فیلترها، مرتب‌سازی، لینک‌ها به‌صورت `text[]` با ایندکس GIN، فیلدهای معکوس محاسبه‌شده، پیوست‌ها به‌صورت `jsonb`، تاریخ‌ها ISO).
  - `deploy/server/zitejs-shim/backend.mjs` → `createEndpoint` و `ZiteError`.
  - `deploy/web/shims/api.ts` → فراخوانی `POST /api/<name>`؛ `deploy/web/shims/upload.ts` → آپلود روی سرور.

## فهرست مو به موی کارها
### ۱. دیتابیس (PostgreSQL) — `deploy/server/schema.sql`
- [x] ۱۱ جدول: ProjectRequests, Admins, Customers, Services, Invoices, Payments, BankAccounts, Notifications, SiteSettings, ActivityLog, ContentItems
- [x] کلید اصلی متنی (حفظ شناسه‌های قبلی هنگام انتقال)، `createdAt` خودکار
- [x] ایندکس یکتا: نام کاربری مدیر، نام کاربری مشتری، کلید تنظیمات
- [x] ایندکس‌های GIN برای لینک‌ها و ایندکس وضعیت فاکتور/نوع محتوا
- [x] View `CustomersServices` برای کوئری‌های داشبورد
- [x] Idempotent (در هر دپلوی اجرا می‌شود)

### ۲. سرور API — `deploy/server/src`
- [x] `index.ts`: Express، اجرای endpointها، اعتبارسنجی ورودی با zod، نگاشت خطا به کد HTTP، محدودیت نرخ per-IP، آپلود امن (پسوند مجاز، نام تصادفی، nosniff)، `/api/health`
- [x] زمان‌بند داخلی صدور فاکتور (هر ساعت بررسی، هر ۶ ساعت اجرا) — دیگر نیازی به بازدید سایت نیست
- [x] `admin.ts`: ساخت/ریست مدیر با نام کاربری و رمز دلخواه از خط فرمان
- [x] `seed.ts`: انتقال کامل داده‌ها با حفظ شناسه‌ها و لینک‌ها
- [x] `billing.ts`: اجرای دستی چرخهٔ صدور فاکتور
- [x] `env.ts`: نگاشت `SESSION_SECRET` و دامنه

### ۳. فرانت‌اند — `deploy/web`
- [x] بیلد Vite با همان کد React، Tailwind و کامپوننت‌ها
- [x] `index.html` فارسی/راست‌چین، متا، manifest و service worker (نصب پرتال روی موبایل)، robots.txt (عدم ایندکس /admin و /portal)

### ۴. پنل مدیریت `/admin` (کامل)
- [x] ورود با نام کاربری/رمزی که خودتان با `npm run admin` می‌سازید (یا صفحهٔ راه‌اندازی اولیه وقتی هیچ مدیری نیست)
- [x] داشبورد مالی (درآمد ماه، مطالبات، معوق‌ها، رسیدهای در انتظار، نمودار ۱۲ ماه، سررسیدهای نزدیک، آخرین فعالیت‌ها)
- [x] فاکتورها (صدور دستی، صدور برای سرویس، تسویه، لغو، چاپ/PDF)
- [x] تأیید/رد رسیدها → تسویهٔ فاکتور و جلو رفتن سررسید سرویس + اعلان به مشتری
- [x] مشتریان (نام کاربری/رمز پرتال، فعال/غیرفعال)، سرویس‌های دوره‌ای، حساب‌های بانکی
- [x] درخواست‌های پروژه، مدیریت محتوا (نمونه‌کار فقط با لینک)، تنظیمات، مدیران و نقش‌ها، لاگ فعالیت

### ۵. پرتال مشتری `/portal`

## کارهای سمت شما
1. رکورد DNS دامنه → آی‌پی سرور
2. اجرای دستورات بخش «روش ۱» در `deploy/README.md`
3. ساخت حساب مدیر با نام کاربری و رمز دلخواه
4. خروجی دستورات را (به‌خصوص اگر خطایی بود) برای بررسی بفرستید
